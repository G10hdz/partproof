# A5: interfaz

**Máquina:** M2 · **Rama:** `feat/a5-ui` · **Empieza en:** C0 · **Ruta feliz desde:** C2 · **Desbloquea:** C3

## Misión

Las pantallas que el jurado ve. Todo en español, servidor primero: las páginas son Server Components que leen SQLite; solo `CaptureForm` y los botones de aprobar son Client Components. No es un SPA.

Antes de dibujar, leer `docs/superpowers/specs/2026-10-09-interface-mockup.md` (referencias y recorrido de pantallas) si existe.

## Rutas que posee

`src/app/page.tsx`, `layout.tsx`, `globals.css`, `src/app/proposals/`, `ledger/`, `settings/`, `mcp-log/`, `watch/`, `src/app/actions.ts`, `src/components/*`, `src/lib/queries.ts`, `tests/queries.test.ts`.

## Tareas

Código exacto: Plan, "Workstream A5". Hasta que lleguen A2, A3 y A4 se trabaja contra los stubs y la semilla; las páginas con propuestas quedan vacías, es lo esperado.

- [ ] **A5.1 Consultas, layout y banner.** `fleetRows`, `proposalById`, `recentProposals`, `mcpLog`; `Banner` con modo de pago (`REAP SANDBOX`/`MOCK`), visión (`EN VIVO`/`REPETICIÓN`) y telemetría `SIMULADA`; navegación. 1 prueba.
- [ ] **A5.2 Flota, propuesta y acciones.** Página de flota con stock/mínimo y vida de cada pieza, formulario de foto, lista de solicitudes; página de propuesta con `GateChecklist` (✔/✘ con la razón de cada regla y los descartados) y `ApproveButtons` (deshabilitado si no está `proposed` o el gate falló); `approveAction` y `rejectAction`.
- [ ] **A5.3 Libro, ajustes, registro MCP y reloj.** Libro por máquina y por hora con total del mes contra presupuesto; ajustes de solo lectura; registro MCP que muestra la nota como dato; pantalla `/watch/[id]` compacta con un toque para aprobar.
- [ ] Verificar: `npx tsc --noEmit && npm run build`; a mano en el navegador con una propuesta creada por el CLI de A2. Push y aviso: "A5 listo para merge".

## Consume

De A3: `approveAndPay`, `rejectProposal`, `ledgerByMachine`, `monthTotalMxn`, `getProviderMode`. De A4: `getVisionMode` y la ruta `/api/vision/analyze`. De Task 0: `getDb`, `getItem`, `getCompany`.

## Produce

Páginas `/`, `/proposals/[id]`, `/ledger`, `/settings`, `/mcp-log`, `/watch/[id]`; acciones `approveAction(id)` y `rejectAction(id)`.

## Reglas de honestidad de la UI

- El banner siempre visible; nada simulado se muestra como real.
- Aprobar deshabilitado cuando el gate falla; la razón visible en español.
- El texto de la nota se muestra como texto plano, nunca interpretado.

## Terminado cuando

- `tests/queries.test.ts` verde, `tsc` y `npm run build` limpios.
- A mano: la flota muestra 4 máquinas; una propuesta verde se aprueba y aparece en el libro; una roja no se puede aprobar y explica por qué.
